# Gemini 4 Argon через Gemini App

Локальный форк `feat/gemini-web-argon`, база upstream v4.2.0. Провайдер
`gemini-web`, публичная модель `gemini-4-argon-web`.

Это ограниченный адаптер веб-чата через неофициальную библиотеку
[Gemini-API](https://github.com/HanaokaYuzu/Gemini-API), закреплённую на коммите
`1ad0d4a93e505e77c79769d78ef2997641f973c8`. Он не добавляет доступ к модели,
если её нет в Gemini App конкретного аккаунта. После входа клиент получает
список доступных моделей и выбирает доступную запись с именем Gemini 4 Argon
или Argon. При отсутствии однозначного имени возвращается 404. Подмены Pro,
Flash или моделью по умолчанию нет; неизвестные идентификаторы не угадываются.

## Возможности и ограничения

- Текстовый чат, история диалога, обычный ответ и SSE-поток через
  `/v1/chat/completions`. Текстовые запросы Responses и Anthropic проходят
  через существующие преобразователи ротатора.
- Каждый запрос создаёт временный веб-чат. История пересылается текстом;
  нативная роль system не обещается. Один постоянный Python-процесс на аккаунт
  сохраняет клиент между запросами и обновляет cookies в фоне. Связь с
  ротатором идёт через приватный Unix socket, публичного HTTP-сервиса нет.
- Кроме экспериментального `read`, API tools, изображения, вложения, аудио и структурированный
  вывод отклоняются с 400. Temperature, token limits, stop и reasoning effort
  не управляют веб-моделью и не гарантируются. Для клиента лучше передавать
  только model, messages и stream.
- Максимум 48 000 байт UTF-8 на весь сформированный контекст и 128 000 символов
  ответа. 16 000 в каталоге — ориентир адаптера, не нативное окно Argon.
- Одновременно один запрос на cookie-файл. Следующий ждёт освобождения
  сессии до 60 секунд; только после истечения ожидания возвращается 409.
  Общий таймаут 480 секунд включает ожидание; отмена клиента останавливает worker.
- Реальные счётчики токенов и остаток веб-квоты недоступны. В каталоге есть
  `usage_unavailable`, в ответах — `X-Rotator-Usage: unavailable`.
  Нулевые счётчики старых совместимых форматов означают отсутствие измерений.
- Ошибка авторизации отключает только credential `gemini-web`. Остальные
  credentials родительского аккаунта не помечаются заблокированными.
- Вход проверяет доступность Argon без генерации. Гостевая сессия, которую
  библиотека может открыть при истёкших cookies, возвращает 401 до выбора модели.

## Локальный запуск

Нужны Node.js >=22, Python >=3.11 и доступ к Gemini App из сети процесса.
Все команды выполняются из корня форка. Используйте отдельный каталог
данных, чтобы пробный экземпляр не менял рабочий ротатор.

```sh
npm ci
python3 -m venv .venv-gemini-web
.venv-gemini-web/bin/pip install -r requirements-gemini-web.txt
export TUXEVIL_ROTATOR_GEMINI_WEB_PYTHON="$PWD/.venv-gemini-web/bin/python"
export TUXEVIL_ROTATOR_DIR="$HOME/.tuxevil-rotator-argon"
npm run login -- --provider gemini-web
npm start
```

Login запрашивает идентификатор аккаунта и способ входа. По умолчанию открывается
отдельный профиль Firefox: войдите в Google, откройте Gemini App и закройте
это окно. Cookies сохраняются автоматически с правами 600; доступность Argon
проверяется без генерации. Повторный вход использует тот же профиль.

### Вход на рабочий сервер с локального компьютера

На этом компьютере установлена команда:

```sh
rotator-gemini-login
```

Она открывает чистый профиль Firefox: войдите в нужный Google-аккаунт,
проверьте Argon и закройте окно. Команда сама получает email и постоянный
Google ID из авторизованной страницы Gemini App. По ID определяется,
добавить аккаунт или обновить существующий. Имя и пути указывать не нужно.
Для каждого аккаунта сохраняется отдельный файл сессии; смена cookies при
повторном входе не создаёт дубликат. Чистый профиль используется, чтобы
несколько Google-аккаунтов в одном браузере не перепутали выбранную сессию;
в нём нужно авторизоваться заново при каждом запуске команды.

После закрытия окна сессия переносится на `root@rotator.lyod.online` через
SSH. Значения передаются через stdin, не попадают в аргументы процесса или
вывод. Сервер проверяет Argon и обновляет аккаунт без перезапуска ротатора.
Если проверка не удалась, прежний файл cookies восстанавливается.

Из исходников эквивалентная команда:

```sh
python3 src/providers/gemini-web/browser_login.py --server root@rotator.lyod.online
```

Локальные файлы сессий: `~/.config/tuxevil-rotator/gemini-web/<hash Google ID>/cookies.json`.
На сервере соответствие ID существующим аккаунтам хранится в приватном
`/var/lib/tuxevil-rotator-gemini-session/account-identities.json` (права 600).
Старый аккаунт `gemini-web-session@local` уже привязан к своему Google ID:
повторный вход обновляет его, сохраняя прежние пути и остальные аккаунты.

Если вход уже выполнен локально, `--upload-only --cookies-file /path/to/cookies.json`
повторяет определение аккаунта и перенос. Без `--cookies-file` используется
прежний файл `~/.config/tuxevil-rotator/gemini-cookies.json`.
Ручной режим с `--email`, `--profile` и явными путями также сохранён.

На сервере cookies и `.gemini-web-cache` находятся в постоянном томе `/sessions`.
Проверка аккаунта после старта запускает постоянный процесс; библиотека
обновляет cookies примерно каждые 10 минут, а после каждого запроса они
сохраняются на диск. Перезапуск контейнера использует этот cache.
Отмена запроса освобождает очередь аккаунта. Google может отозвать сессию;
в таком случае повторите `rotator-gemini-login`. Это веб-сессия Google,
она не использует OAuth refresh token провайдера Antigravity.

### Импорт существующего файла

Способ входа `file` по-прежнему принимает абсолютный путь к JSON. Форма файла:

```json
{
  "__Secure-1PSID": "<значение из вашей сессии Gemini App>",
  "__Secure-1PSIDTS": "<значение из той же сессии>"
}
```

Значения cookies не вставляйте в чат, командную строку или git. Файл должен
читаться только пользователем процесса (`chmod 600`), родительский каталог —
быть доступен ему на запись: рядом создаётся `.gemini-web-cache` с обновлёнными
cookies и блокировкой. Ротатор хранит в accounts.json только путь. Вариант
credential для ручной настройки существующего аккаунта:

```json
{"provider":"gemini-web","cookiesFile":"/absolute/private/gemini.json"}
```

Если авто-включение новых моделей отключено, включите
`gemini-web/gemini-4-argon-web` на странице Models. Не используйте псевдоним
Antigravity для веб-модели. Наличие модели в каталоге при ручной настройке
credentials означает настроенный маршрут; окончательная проверка реального
доступа выполняется перед генерацией, либо при CLI login.

Пример запроса к отдельному тестовому экземпляру (порт выбирается его конфигом):

```sh
curl http://127.0.0.1:51200/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"gemini-4-argon-web","messages":[{"role":"user","content":"Привет"}],"stream":true}'
```

При настроенной авторизации добавьте свой API-ключ ротатора обычным способом.
Cookies Google API-клиенту не передаются.

## Экспериментальный read через OpenAI Chat Completions

В исходниках добавлен прототип одного инструмента `read`. Клиент передаёт
единственную OpenAI function с именем `read` и схемой параметров с текстовым
`path`. Поддерживаются `tool_choice: auto` и `none`; принудительный вызов пока
не поддерживается. Другие инструменты отклоняются. Общий каталог по-прежнему
не обещает полноценный tool calling.

Адаптер описывает инструмент веб-модели текстом и принимает запрос чтения
только с уникальным маркером текущего запроса. Имя и аргументы проверяются,
ответ преобразуется в стандартный `tool_calls`. Чтение выполняет клиент на
своей машине, затем отправляет сообщение `role: tool`. Результат включается
в следующий запрос целиком в пределах общего лимита 48 000 байт. Для этого
режима ответ буферизуется до завершения; обычный текстовый чат остаётся
потоковым. Это эмуляция инструментов через текст, а не нативный API Gemini.

После установки прототипа запуск omp ограничивается одним инструментом:

```sh
omp --model tuxevil-rotator/gemini-4-argon-web --tools read \
  --no-lsp --no-extensions --no-skills --no-title --no-session --thinking off
```

Существующий `omp-argon` продолжает запускать текстовый режим с `--no-tools`.
Прототип включён в образ с постоянной сессией `tuxevil-rotator:argon-auth-test`.
Проверка прежнего образа 15 октября 2026 года получила 401 из-за истёкшей
сессии; после входа через Firefox доступ Argon подтверждён. Полный цикл
инструмента с настоящим Argon отдельно не проверен.

Локально проверены API-цикл вызов → результат → ответ, потоковый `tool_calls`,
проверка аргументов, запрет других инструментов и передача результата длиннее
500 символов без прежнего сокращения преобразователем Antigravity.
Отдельно настоящий omp прошёл полный цикл с имитацией веб-ответа: выполнил
`read` для локального файла со случайной меткой, вернул результат в ротатор
и получил эту метку в окончательном ответе (код завершения 0).
Полный `npm run check`: 1 244 теста прошли, 2 пропущены; проверки типов и
ESLint без ошибок (15 прежних предупреждений).

## Контейнер

```sh
docker build -f Dockerfile.gemini-web -t tuxevil-rotator:argon .
```

Используйте отдельные тома `/data` и `/sessions`. `/sessions` должен быть
доступен пользователю node (uid 1000) на запись для cache. Путь credentials
указывается внутри контейнера, например `/sessions/gemini.json`. Для входа
используйте тот же образ и те же тома, переопределив команду на
`node --import tsx/esm src/cli.ts login --provider gemini-web`.
Рабочий контейнер не заменяется автоматически.

## Проверки без Google

```sh
npm run typecheck
npm run typecheck:test
TUXEVIL_ROTATOR_DIR=/tmp/argon-contract-state node --import tsx/esm --test test/gemini-web.test.ts
npm run test:gemini-web
python3 -m py_compile src/providers/gemini-web/{worker,session,browser_login}.py
```

Тесты не используют настоящие cookies и не обращаются к Gemini App. Они
проверяют выбор Argon без fallback, историю, Unicode, SSE, ошибки до и после
начала потока, блокировку сессии, ограничение вывода и отмену worker. Отдельные
проверки запускают настоящий постоянный процесс с имитацией Google-клиента:
повторное использование, фоновое обновление и восстановление cache после
перезапуска. Вход проверяется на тестовой SQLite-базе Firefox, перенос по SSH —
на имитации сервера, включая откат cookies при отказе авторизации.
