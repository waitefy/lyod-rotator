# Gemini 4 Argon через Gemini App

## Постоянный Go-движок

В образ включён `rotator-gemini-engine`, собранный из закреплённого исходника
[Gemini-Sentinel](https://github.com/Sonesh-2202/Gemini-Sentinel).
Ревизия, SHA-256 исходников и MIT-лицензия зафиксированы в `gemini-engine.json`;
исходники донора сохранены без правок в `third_party/gemini-sentinel`.
Наши дополнения и проверяемые патчи находятся в `engines/gemini-web`.
Zexadev и ikhsan3adi остаются сравнительными реализациями: три API-прокси
друг за другом не запускаются.

Выбор движка: `TUXEVIL_ROTATOR_GEMINI_WEB_BACKEND=go` или `python`.

`TUXEVIL_ROTATOR_GEMINI_WEB_PROXY` задаёт общий исходящий прокси только для
Gemini App: вход, проверка квоты и генерация используют один маршрут. Настройка
`credentials[].proxyUrl` конкретного аккаунта имеет приоритет; пустая строка
явно выбирает прямое соединение. После изменения общего прокси перезапустите
ротатор, чтобы существующие процессы движка приняли новый маршрут.

Временный маршрут через ПК: пользовательский сервис
`rotator-gemini-egress.service` поддерживает SSH-туннель с серверного
`127.0.0.1:12081` на локальный прокси ПК `127.0.0.1:2080`.
Сервер использует `TUXEVIL_ROTATOR_GEMINI_WEB_PROXY=http://127.0.0.1:12081`.
ПК, его прокси и SSH-соединение должны оставаться включёнными; при обрыве
сервис автоматически переподключается. Порт доступен только на loopback сервера.
Управление на ПК: `systemctl --user status rotator-gemini-egress.service`,
`systemctl --user stop rotator-gemini-egress.service`.

По умолчанию в исходниках остаётся Python; переключение рабочего развёртывания
производится только после отдельной проверки Go. Автоматического перехода между
движками при ошибке нет. API, три имени Low/Medium/High и маршрутизация аккаунтов
остаются у ротатора. Путь к бинарнику при запуске из исходников задаётся через
`TUXEVIL_ROTATOR_GEMINI_WEB_ENGINE`; в Docker он установлен автоматически.

Go получает структурированные сообщения, схемы и результаты инструментов,
inline-изображения и PDF/TXT/CSV, а затем адаптирует их к веб-протоколу.
На каждый cookie-файл работает один постоянный процесс с приватным Unix-сокетом
(0600), без TCP-порта. Cookies и кэш продолжений находятся в
`.gemini-web-engine/<hash пути cookie-файла>` рядом с сессиями; этот каталог
нужно сохранять в существующем томе `/sessions`. Другой корень можно задать
`TUXEVIL_ROTATOR_GEMINI_ENGINE_STATE_DIR`. Полный набор cookies импортируется
при первом запуске или изменении файла после браузерного входа. Повторный запуск
не заменяет обновлённые cookies старым снимком. Активировать одновременно два
движка для одного аккаунта не следует: у обновления сессии должен быть один хозяин.

Обычные диалоги используют серверные продолжения. Кэш изолирован по аккаунту,
модели, уровню, истории, system-инструкции и инструментам; живёт 30 минут,
сохраняется между перезапусками и ограничен 256 записями. Это оптимизация:
при отсутствии подходящего продолжения отправляется полная история.
Такие чаты могут появляться в истории Gemini App. Для генерации изображений
используется временный чат. Нативная роль system и точные API-счётчики токенов
по-прежнему не гарантируются.

Общий срок одного вызова Go — 240 секунд, внешний watchdog — 245 секунд;
ожидание свободной сессии ограничено 10 секундами. Отмена клиента прерывает
HTTP-запрос. Проверенный текст передаётся постепенно; вызовы инструментов
выдаются только после полного успешного ответа и проверки схем. Потерянный
поток не приводит к повторному выполнению уже выданного инструмента.
Скрытой подмены на другую модель нет; несовпадающий ID нельзя оправдать
совпадающим названием. Уже отправленный текст отозвать невозможно.

Локальная сборка и целевые проверки (Go указан в go.mod):

```bash
CGO_ENABLED=0 ROTATOR_ENGINE_TEST=1 node scripts/build-gemini-engine.mjs /tmp/rotator-gemini-engine
node --import tsx/esm --test test/gemini-web-engine.test.ts test/gemini-web.test.ts
npm run typecheck
npm run typecheck:test
```

Docker собирает и проверяет движок в отдельном этапе; компилятор Go не попадает
в рабочий образ. `build-info.json` содержит ревизии ротатора, движка и Python-клиента.
Сборка выполняется на ПК или CI, сервер получает готовый образ.

Обновление основного tuxevil rotator продолжает обслуживать `argon-upstream-sync`.
`argon-engine-sync` раз в неделю проверяет донора при включённом
`ARGON_UPSTREAM_SYNC_ENABLED`, закрепляет новый commit и создаёт draft PR только
после успешного применения патчей, тестов и сборки. Для обоих workflow используется
существующий `UPSTREAM_SYNC_TOKEN`. Полный CI и реальные проверки текста,
инструментов и вложений требуются перед продвижением. Автоматического merge
и развёртывания нет. Если изменился протокол или патч не применяется, обновление
останавливается. Вручную: `node scripts/update-gemini-engine.mjs <полный commit>`.
Для отката сохраните предыдущий образ и установите `BACKEND=python` с полным
именем переменной выше; перезапустите контейнер, сохранив `/data` и `/sessions`.

Описанные ниже детали Python-брокера, временных чатов и его таймаутов относятся
к прежнему движку. Общие возможности API и ограничения форматов сохраняются.


Локальный форк `feat/gemini-web-argon`, база upstream v4.2.0. Провайдер
`gemini-web`, три публичные модели: `gemini-4-argon-web-low`,
`gemini-4-argon-web-medium` и `gemini-4-argon-web-high`.

Уровень фиксируется именем модели и не меняется через `reasoning_effort`.
Это три варианта одной Argon, соответствующие Low / Medium / High в Gemini App.
В веб-протоколе они имеют значения `1` / `4` / `2`: поле 81 тела запроса
и поле 16 заголовка выбора модели. Значение `3` относится к Deep Think
и не используется. Адаптер проверяет формат закреплённой версии библиотеки
перед отправкой; при несовпадении возвращает ошибку. Старый адрес
`gemini-4-argon-web` поддерживается как Low, но не публикуется в каталоге.
Общий пул сессий и ограничения возможностей одинаковы для всех вариантов.

[Google: модели и уровни размышления](https://support.google.com/gemini/answer/18648722?hl=en).

Это ограниченный адаптер веб-чата через неофициальную библиотеку
[Gemini-API](https://github.com/HanaokaYuzu/Gemini-API), закреплённую на коммите
`1ad0d4a93e505e77c79769d78ef2997641f973c8`. Он не добавляет доступ к модели,
если её нет в Gemini App конкретного аккаунта. После входа клиент получает
список доступных моделей и выбирает доступную запись с именем Gemini 4 Argon
или Argon. При отсутствии однозначного имени возвращается 404. Подмены Pro,
Flash или моделью по умолчанию нет; неизвестные идентификаторы не угадываются.

Воркер проверяет ограниченный ответ StreamGenerate (не более 16 МиБ) и сверяет
серверный ID из `inner[39]` с ID выбранной записи каталога. Обычный текст
передаётся в SSE по мере поступления после первой корректной метки Argon.
Если метка появляется поздно, предшествующий текст удерживается до неё.
Если Google отдаёт весь текст одним фрагментом, адаптер не имитирует печать.
При отсутствующей или повреждённой метке
воркер один раз повторяет запрос с тем же выбранным Argon, если клиенту ещё
не отправлено ни одного события. Если повтор тоже не проверен, возвращается
502 с безопасной причиной: `missing model identifier` или
`invalid response metadata`. После начала ответа повтор запрещён. Другой
ID прерывает ответ с 429 и временной паузой аккаунта;
ошибки авторизации, квоты и отклонения модели не получают этот повтор.
Это проверка недокументированной серверной метки, а не независимое
доказательство исполнения конкретных весов Google. Итоговая проверка всего
ответа остаётся обязательной перед успешным завершением. Поздняя ошибка или
смена ID прерывает поток; уже показанный текст отозвать невозможно. После
начала HTTP 200 клиент получает ошибку потока, а не новый HTTP-статус.
Изображения и вызовы инструментов удерживаются до итоговой проверки. При
включённых инструментах обычный текст начинает передаваться, когда его начало
уже не может совпасть с маркером вызова. Пробелы и разрезанные маркеры ждут
продолжения. При обязательном вызове инструмента текст не выпускается.

В том же буфере проверяются явные коды ошибок Google из поля
`part[5][2][0][1][0]`, которое использует закреплённая библиотека.
Ошибка в конце ответа блокирует вызовы инструментов и завершает текстовый поток
с ошибкой, если он уже начался. Код `1013`
означает временный отказ: разрешён один повтор через секунду, с тем же
Argon и только до первого события клиенту. Квота `1037`, отклонение модели
`1050`/`1052`, блокировка IP `1060` и неизвестные коды этого повтора не
получают. Их безопасный числовой код включается в ошибку вместо сообщения
об отсутствующем ID модели. Содержимое исключений библиотеки не передаётся.

Каждый вызов Python-воркера пишет одну итоговую строку `[gemini-web]` в журнал
ротатора: случайный `diagnosticId`, операцию `text`/`image`/`probe`, исход,
HTTP-статус, общее время `workerMs` и время до `ready` (`readyMs`). Приватное
событие `diagnostic` не передаётся API-клиенту. В нём разрешены только:
`sessionMs`, число попыток адаптера `attempts`, число фактических вызовов
StreamGenerate `googleRequests` (включая повторы библиотеки), известная категория
ошибки `errorKind`, этап отказа `failedStage` и числовой `googleCode`, если он есть.
Таймеры `timingsMs` разделяют ожидание брокера (`sessionWait`), файловую блокировку
(`fileLock`), инициализацию (`init`), выбор модели (`modelSelection`), квоту
(`quota`), генерацию (`generation`), HTTP-обмен с Google (`googleRequest`),
скачивание картинки (`imageDownload`) и сохранение сессии (`persist`).
`generation` включает загрузку входных файлов, повторы и скачивание результата;
`googleRequest` вложен в него и включает чтение и проверку ответа. Складывать
вложенные таймеры нельзя. Очередь ротатора измеряется отдельно существующим
`queueMs`. Промпты, ответы, пути cookies, аккаунты, URL, заголовки и тексты
исключений в эти строки не включаются; TypeScript повторно фильтрует поля.
При отмене, аварии процесса или тайм-ауте внешнего watchdog подробности могут
не успеть поступить: тогда остаются общий статус и `workerMs`. Значение кода
`1100` пока неизвестно; диагностика не добавляет повторов и не отключает
проверку модели.

Перед генерацией обновляются доступные счётчики compute за 5 часов и неделю.
Исчерпание любого окна приостанавливает аккаунт до его сброса; при нескольких
исчерпанных окнах используется самый поздний сброс. Ротатор может повторить
запрос на другом доступном аккаунте Gemini Web в пределах настроенного
лимита повторов, сохраняя Low / Medium / High. Если замены нет, возвращается
ошибка провайдера.

До начала ответа HTTP 401, 403, 409, 503 и 504 также разрешают переход
на другой доступный аккаунт Gemini Web в пределах `streamRecoveryMaxRetries`.
401 помечает только веб-сессию как требующую входа, 403 приостанавливает её
на минуту, занятость и временные сбои — на 15 секунд. OAuth и остальные
провайдеры аккаунта не затрагиваются. Без замены сохраняется исходная ошибка;
400, 404 и 502 не запускают такой повтор. Выбранная модель и уровень
размышления при смене аккаунта сохраняются.

Реальная проверка трёх уровней: исходящие значения `1`, `4`, `2`
проверены перед отправкой, каждый запрос получил ожидаемый текстовый ответ
от Google. Это проверяет передачу уровня и работоспособность генерации,
но не измеряет внутренний бюджет размышления Google.

Установлено на `rotator.lyod.online`, образ `tuxevil-rotator:argon-levels`,
служба `tuxevil-rotator-stage.service`. Через `/v1/models` опубликованы ровно
три варианта; каждый проверен через `/v1/chat/completions` с HTTP 200.
OMP подтвердил ответ Medium; в локальный `models.yml` добавлены три отдельных
имени с `reasoning: false`, чтобы клиент не предлагал дополнительный effort.
Это настройка интерфейса клиента: сервер выбирает веб-уровень по ID модели.
Прежний выбор OMP переведён на Low, сохраняющий прежний уровень.
Сохранены 9 записей аккаунтов, 4 веб-сессии и прежние отключения.
Резервная копия: `/root/rotator-backups/20261015T184055Z-argon-levels`.
Проверки: 1 246 TypeScript-тестов прошли, 2 пропущены; 26 Python-тестов прошли;
проверки типов и ESLint без ошибок (15 прежних предупреждений).

## Возможности и ограничения

- Текстовый чат с inline-изображениями и документами, история диалога,
  обычный ответ и SSE-поток через `/v1/chat/completions`. Responses и Anthropic проходят
  через существующие преобразователи ротатора.
- Генерация одного изображения через `/v1/images/generations` с ответом
  `b64_json`, Responses с `image_generation` и Gemini GenerateContent с
  IMAGE-модальностью. Параметры и ограничения описаны ниже; эти маршруты
  не зависят от расширений OMP или OpenCode.
- Каждый запрос создаёт временный веб-чат. История пересылается текстом;
  вложения из истории загружаются заново; нативная роль system не обещается. Один постоянный Python-процесс на аккаунт
  сохраняет клиент между запросами и обновляет cookies в фоне. Связь с
  ротатором идёт через приватный Unix socket, публичного HTTP-сервиса нет.
- Поддерживаются экспериментальные function tools с произвольными именами
  и проверяемыми схемами клиента. Аудио, видео и структурированный
  вывод отклоняются с 400. Temperature, token limits, stop и reasoning effort
  не управляют веб-моделью и не гарантируются. Для клиента лучше передавать
  только model, messages и stream.
- Максимум 4 194 304 байт (4 МиБ) UTF-8 на весь сформированный контекст и 128 000 символов
  ответа. 262 144 токена в каталоге — ориентир адаптера, не нативное окно Argon.
- Одновременно один запрос на cookie-файл. Следующий ждёт освобождения
  сессии до 60 секунд; только после истечения ожидания возвращается 409.
  Общий таймаут 480 секунд включает ожидание; отмена клиента останавливает worker.
- Реальные счётчики токенов недоступны. Остаток compute за 5 часов и неделю
  отображается, если библиотека получила эти данные от Google; неизвестная
  квота не считается нулевой. В каталоге есть
  `usage_unavailable`, в ответах — `X-Rotator-Usage: unavailable`.
  Нулевые счётчики старых совместимых форматов означают отсутствие измерений.
- Ошибка авторизации отключает только credential `gemini-web`. Остальные
  credentials родительского аккаунта не помечаются заблокированными.
- Вход проверяет доступность Argon без генерации. Гостевая сессия, которую
  библиотека может открыть при истёкших cookies, возвращает 401 до выбора модели.

## Локальный запуск

Нужны Node.js >=22, Python >=3.11 и доступ к Gemini App из сети процесса.
Все команды выполняются из корня форка. Используйте отдельный каталог
данных, чтобы пробный экземпляр не менял рабочий ротатор.

```sh
npm ci
python3 -m venv .venv-gemini-web
.venv-gemini-web/bin/pip install -r requirements-gemini-web.txt
export TUXEVIL_ROTATOR_GEMINI_WEB_PYTHON="$PWD/.venv-gemini-web/bin/python"
export TUXEVIL_ROTATOR_DIR="$HOME/.tuxevil-rotator-argon"
npm run login -- --provider gemini-web
npm start
```

Login запрашивает идентификатор аккаунта и способ входа. По умолчанию открывается
отдельный профиль Firefox: войдите в Google, откройте Gemini App и закройте
это окно. Cookies сохраняются автоматически с правами 600; доступность Argon
проверяется без генерации. Повторный вход использует тот же профиль.

### Вход на рабочий сервер с локального компьютера

На странице Accounts кнопка **Connect Gemini App** открывает вход через локальный
помощник. Для существующего аккаунта используйте **Reconnect Gemini App** в его
меню или в сообщении об ошибке авторизации. Помощник открывает отдельное окно
Firefox на ПК; после входа закройте это окно. Cookies передаются через SSH,
сервер проверяет Argon и обновляет аккаунт без перезапуска. Страница автоматически
обновляет состояние подключения; исчерпание квоты повторный вход не снимает.

На Linux помощник устанавливается один раз на каждом компьютере:

```sh
python3 src/providers/gemini-web/desktop_login.py --install \
  --server root@rotator.lyod.online --origin https://rotator.lyod.online
```

Нужны Firefox, Python 3, `xdg-mime` и настроенный SSH-доступ. Окна результата
показывает `zenity` (при его отсутствии — `notify-send`). Браузер может запросить
разрешение открыть приложение **Rotator Login**. На компьютере без установленного
помощника кнопка сама по себе не выполняет вход; доступна прежняя CLI-команда ниже.
Мобильный и Windows/macOS-вход этим Linux-помощником не поддерживаются.

Обработчик `tuxevil-gemini://` принимает только origin сайта и ожидаемый email.
SSH-сервер задаётся при установке и не может быть заменён ссылкой с сайта.
При повторном входе email проверяется до загрузки cookies; другой аккаунт не
заменит выбранный. Отдельные профили Firefox сохраняются в
`~/.config/tuxevil-rotator/desktop-profiles/` и повторно открываются при следующем
подключении. Пароли не сохраняются менеджером паролей Firefox. Не передавайте
эти профили другим людям: в них находится сессия Google.

На этом компьютере установлена команда:

```sh
rotator-gemini-login
```

Она открывает чистый профиль Firefox: войдите в нужный Google-аккаунт,
проверьте Argon и закройте окно. Команда сама получает email и постоянный
Google ID из авторизованной страницы Gemini App. По ID определяется,
добавить аккаунт или обновить существующий. Имя и пути указывать не нужно.
Для каждого аккаунта сохраняется отдельный файл сессии; смена cookies при
повторном входе не создаёт дубликат. Чистый профиль используется, чтобы
несколько Google-аккаунтов в одном браузере не перепутали выбранную сессию;
в нём нужно авторизоваться заново при каждом запуске команды.

После закрытия окна сессия переносится на `root@rotator.lyod.online` через
SSH. Значения передаются через stdin, не попадают в аргументы процесса или
вывод. Сервер проверяет Argon и обновляет аккаунт без перезапуска ротатора.
Если проверка не удалась, прежний файл cookies восстанавливается.

Из исходников эквивалентная команда:

```sh
python3 src/providers/gemini-web/browser_login.py --server root@rotator.lyod.online
```

Локальные файлы сессий: `~/.config/tuxevil-rotator/gemini-web/<hash Google ID>/cookies.json`.
На сервере соответствие ID существующим аккаунтам хранится в приватном
`/var/lib/tuxevil-rotator-gemini-session/account-identities.json` (права 600).
При входе сервер сам получает email и Google ID из авторизованной Gemini App
и сохраняет ID в `credentials[].providerAccountId`, как идентификатор у Codex.
Если такой email уже есть в ротаторе, Gemini App добавляется к его провайдерам.
Старые записи `@local`, содержащие только эту веб-сессию, удаляются после
успешной привязки к реальному аккаунту. Пути cookies и cache сохраняются.

В таблице Providers показывается один пул Gemini App. Окна 5 часов и недели
совместно ограничивают его квоту: показывается наиболее ограничивающее окно,
а при исчерпании нескольких окон — наиболее поздний сброс. Значения обоих
окон остаются в подробностях последнего опроса аккаунта.

Если вход уже выполнен локально, `--upload-only --cookies-file /path/to/cookies.json`
повторяет определение аккаунта и перенос. Без `--cookies-file` используется
прежний файл `~/.config/tuxevil-rotator/gemini-cookies.json`.
Ручной режим с `--email`, `--profile` и явными путями также сохранён.

На сервере cookies и `.gemini-web-cache` находятся в постоянном томе `/sessions`.
Проверка аккаунта после старта запускает постоянный процесс; библиотека
обновляет cookies примерно каждые 10 минут, а после каждого запроса они
сохраняются на диск. Перезапуск контейнера использует этот cache.
Отмена запроса освобождает очередь аккаунта. Google может отозвать сессию;
в таком случае повторите `rotator-gemini-login`. Это веб-сессия Google,
она не использует OAuth refresh token провайдера Antigravity.

### Импорт существующего файла

Способ входа `file` по-прежнему принимает абсолютный путь к JSON. Форма файла:

```json
{
  "__Secure-1PSID": "<значение из вашей сессии Gemini App>",
  "__Secure-1PSIDTS": "<значение из той же сессии>"
}
```

Значения cookies не вставляйте в чат, командную строку или git. Файл должен
читаться только пользователем процесса (`chmod 600`), родительский каталог —
быть доступен ему на запись: рядом создаётся `.gemini-web-cache` с обновлёнными
cookies и блокировкой. Ротатор хранит в accounts.json только путь. Вариант
credential для ручной настройки существующего аккаунта:

```json
{"provider":"gemini-web","cookiesFile":"/absolute/private/gemini.json"}
```

Если авто-включение новых моделей отключено, включите
`gemini-web/gemini-4-argon-web` на странице Models. Не используйте псевдоним
Antigravity для веб-модели. Наличие модели в каталоге при ручной настройке
credentials означает настроенный маршрут; окончательная проверка реального
доступа выполняется перед генерацией, либо при CLI login.

Пример запроса к отдельному тестовому экземпляру (порт выбирается его конфигом):

```sh
curl http://127.0.0.1:51200/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"gemini-4-argon-web","messages":[{"role":"user","content":"Привет"}],"stream":true}'
```

При настроенной авторизации добавьте свой API-ключ ротатора обычным способом.
Cookies Google API-клиенту не передаются.

## Изображения и документы на вход

Статус: экспериментальная возможность версии `4.2.0-argon.2`. Проверки преобразования запросов, передачи байтов и очистки
файлов проходят. В изолированной проверке с реальным аккаунтом модель
`gemini-4-argon-web-low` прочитала контрольные коды из PNG, PDF и TXT через
Chat Completions, Responses и Anthropic Messages — обычным ответом и SSE.
Каталог объявляет `multimodal: true` для вложений на вход; генерация
картинок включается отдельно описанными ниже параметрами. В прозе маркеры
`[cite: N]` преобразуются в Markdown-ссылки, если выбранный кандидат вернул
соответствующие веб-источники. Неразрешённые маркеры удаляются независимо от
числа вложений, включая изображения из истории диалога. В группе маркеров
сохраняются ссылки на известные источники; соответствие номеров вложениям не
угадывается. Код и аргументы вызовов инструментов не изменяются. Если маркер
разбит между частями ответа, текст начиная с него ожидает финальных метаданных.

Успешные запросы заняли 17–49 секунд. Первые короткие пробы прерывались
по таймауту; один Anthropic SSE завершился `fetch failed` через 301 секунду,
а отдельный повтор с согласованными HTTP-таймаутами прошёл за 26 секунд.
Причина единичного долгого запроса не установлена; проверка подтверждает
чтение файлов, но не гарантирует стабильное время ответа. JPEG, WebP, GIF
и CSV проходят локальные проверки передачи данных; отдельной проверки
их содержимого на реальном аккаунте пока не было.

Адаптер принимает inline-вложения в сообщениях пользователя и результатах
инструментов. Поддерживаемые MIME-типы: `image/png`, `image/jpeg`, `image/webp`,
`image/gif`, `application/pdf`, `text/plain`, `text/csv`. Данные должны быть
корректным base64 с padding. Лимиты адаптера: 5 МиБ на файл, 10 МиБ суммарно,
не более 8 вложений во всей пересылаемой истории. Общий HTTP-лимит тела запроса
ротатора также применяется. Лимит текстового контекста считается отдельно.

| API | Изображение в content | Документ в content |
| --- | --- | --- |
| Chat Completions | `{"type":"image_url","image_url":{"url":"data:image/png;base64,..."}}` | `{"type":"file","file":{"file_data":"data:application/pdf;base64,..."}}` |
| Responses | `{"type":"input_image","image_url":"data:image/png;base64,..."}` | `{"type":"input_file","file_data":"data:application/pdf;base64,..."}` |
| Anthropic Messages | `{"type":"image","source":{"type":"base64","media_type":"image/png","data":"..."}}` | `{"type":"document","source":{"type":"base64","media_type":"application/pdf","data":"..."}}` |

`...` в примерах заменяется данными файла. Один пользовательский ход может
содержать только вложение; в веб-промпт добавляется его номер и MIME-тип.
Файлы передаются библиотеке как отдельные загрузки, а не как base64 в тексте
для модели. Временные файлы находятся в отдельном каталоге с правами 700,
сами файлы имеют права 600 и удаляются при успехе, ошибке и отмене запроса.
Вместо клиентских имён используются `attachment-1.png`, `attachment-2.pdf`
и другие имена с расширением, соответствующим MIME-типу.

HTTP-ссылки, локальные пути и `file_id` не разрешаются; неподдерживаемые
форматы и превышение лимитов дают 400 до обращения к Google. Вложения в
system/assistant не поддерживаются. Форматы создания изображений описаны
ниже; выдача произвольных документов на выходе пока не реализована.
Перезапуск и обновление рабочего сервера
не выполняются автоматически при изменении локального кода.

Тесты `test/gemini-web-attachments.test.ts` проверяют преобразование всех трёх
API, сохранение вложений из прошлых ходов и результатов инструментов,
лимиты и реальный HTTP-путь до имитации worker в JSON/SSE. Python-тесты
`test/gemini_web_attachments_test.py` проверяют точность байтов, расширения,
права доступа и очистку после успеха, ошибки и отмены.

## Создание изображений через Images API

Начиная с `4.2.0-argon.2`, адаптер предоставляет `POST /v1/images/generations` для
`gemini-4-argon-web-low`, `gemini-4-argon-web-medium`,
`gemini-4-argon-web-high` и прежнего псевдонима без суффикса.
Схема ответа соответствует подмножеству
[OpenAI Images API](https://developers.openai.com/api/reference/resources/images/methods/generate):
`created`, `data[0].b64_json`, `output_format`. Счётчики расхода не выдумываются.

```json
{
  "model": "gemini-4-argon-web-low",
  "prompt": "Зелёный робот с оранжевым зонтом на белом фоне",
  "n": 1,
  "response_format": "b64_json"
}
```

`model` и непустой `prompt` обязательны; `n` можно не передавать, его
единственное поддержанное значение — 1. `response_format` по умолчанию
`b64_json`; вариант `url` отклоняется. Необязательный `user` принимается
как метаданные. `size`, `quality`, `style`, `output_format`, `stream` и другие
параметры отклоняются с 400 до обращения к Google. Реальный формат
PNG/JPEG/WebP определяется по байтам и возвращается в `output_format`;
он выбирается веб-сервисом, перекодирования и выбора разрешения нет.
Для скачивания запрашивается увеличенный вариант, аналогично резервному
пути `GeneratedImage.save()` закреплённой библиотеки. Фактический размер
определяет Google; маленькое превью по умолчанию не запрашивается.

Ротатор использует обычные виртуальные ключи, ограничения ключа по модели,
переключатели моделей/провайдеров, очередь аккаунтов и учёт запросов.
Cookie-файлы, прокси и подписанные ссылки Google остаются на сервере.
Worker берёт только `generated_images` выбранного кандидата закреплённой
библиотеки; картинки из веб-поиска не считаются результатом генерации.
Повторные снимки ответа не создают дубликатов. Если сервис вернул несколько
созданных изображений, выдаётся первое.

Скачивание идёт через авторизованный транспорт аккаунта. Разрешён HTTPS
на `googleusercontent.com`, его поддоменах и конкретном хосте
`work.fife.usercontent.google.com`, на который Google перенаправил скачивание
в реальной проверке. Каждый редирект проверяется,
максимум три перехода. Лимит — 8 МиБ декодированных данных. Отмена запроса
закрывает скачивание. HTTP 200 отправляется только после готового изображения
и успешного завершения worker. Отказ модели, отсутствие изображения,
ошибка скачивания или недопустимый формат дают ошибку вместо пустого успеха.
Ответ содержит `Cache-Control: no-store`, `X-Rotator-Usage: unavailable`
и `X-Rotator-Provider-Mode: limited-web`.

Этот маршрут нужно вызывать клиентом, поддерживающим Images API.
Для Responses и Gemini GenerateContent доступны также форматы ниже.
Отдельный маршрут Images Edits, выдача PDF/архивов/прочих документов и
генерация аудио/видео пока не реализованы. Для варианта с исходной картинкой
доступна её явная передача через Responses, как описано ниже.

### Генерация в Pi

Расширение `plugins/pi-gemini-images.js` добавляет инструмент `generate_image`.
Оно использует URL, авторизацию и выбранный уровень Argon из текущей модели
Pi, сохраняет PNG/JPEG/WebP в текущую папку и возвращает блок изображения
для показа. Для создания с нуля вызывается Images API; при передаче
`reference_image` — Responses с `input_image`, обязательным `image_generation`
и `store: false`. Ключи и cookies в расширении не задаются.

Для установки из checkout:

```sh
mkdir -p ~/.pi/agent/extensions
ln -s /path/to/tuxevil-rotator-argon/plugins/pi-gemini-images.js ~/.pi/agent/extensions/rotator-images.js
```

Затем выполните `/reload` в Pi или перезапустите его. Выберите модель
`tuxevil-rotator/gemini-4-argon-web-low` (medium/high также поддерживаются)
и попросите создать картинку обычным текстом. Упоминать инструмент в запросе
не требуется. При явном ограничении списка инструментов разрешите
`generate_image`.

Для изменения или варианта существующей картинки инструмент принимает
`reference_image`: путь к локальному PNG/JPEG/WebP размером до 5 МиБ.
Относительный путь разрешается от текущей папки. В API передаются сами байты
файла, а не его путь или текстовое описание; исходник не изменяется.
Результат сохраняется отдельным файлом. Точное сохранение геометрии и деталей
зависит от Google и не гарантируется. После обновления расширения выполните
`/reload`, чтобы Pi получил новый параметр инструмента.

Существующие файлы не перезаписываются. Повторов запроса при ошибке нет:
генерация могла уже состояться на стороне Google. Ошибка API не превращается
в успешный результат или инструкцию нарисовать картинку самостоятельно.

Проверки: `test/gemini-web-images.test.ts`, `test/gemini_web_images_test.py`
и тест большого события в `test/gemini_web_session_test.py` покрывают
HTTP-путь, ограничения запроса и результата, выбор созданной картинки,
повторы потока, ошибки до HTTP 200, редиректы, лимиты скачивания и отмену.

## Картинки в Responses и Gemini GenerateContent

`POST /v1/responses` принимает стандартный встроенный инструмент
[`image_generation`](https://developers.openai.com/api/docs/guides/tools-image-generation):

```json
{
  "model": "gemini-4-argon-web-low",
  "input": "Нарисуй зелёного робота, читающего синюю книгу",
  "tools": [{ "type": "image_generation" }],
  "tool_choice": { "type": "image_generation" },
  "store": false,
  "stream": false
}
```

Картинка возвращается отдельным элементом `output[]`:
`type: "image_generation_call"`, `status: "completed"`, `result` с base64
и `output_format` с фактическим форматом. При `tool_choice: "auto"`
или отсутствии `tool_choice` результатом может быть картинка либо текст.
Объект `{"type":"image_generation"}` и строка `"required"` требуют
созданную картинку: её отсутствие даёт 502. `"none"` отключает инструмент
и возвращает только текст. Если картинка создана, служебная текстовая
подпись веб-сервиса отбрасывается; чередование текста с картинками пока
не сохраняется. Картинки из веб-поиска не выдаются как созданные.

Поддерживается один инструмент `image_generation` без дополнительных
параметров. Его сочетание с function tools, выбор качества/размера/формата
и частичные превью отклоняются до обращения к Google. `store: false`
обязателен: перенос созданных изображений через сохранённую серверную
историю ещё не реализован. Для следующего хода клиент может явно передать
полученную картинку как `input_image` с data URL — с действующими лимитами
входных вложений. Текущий выходной лимит 8 МиБ больше входного лимита
5 МиБ на файл: слишком большой результат перед повторной отправкой
нужно уменьшить на стороне клиента. Гарантии редактирования картинки нет.

При `stream: true` после полного завершения генерации и скачивания выдаются
стандартные SSE-события `response.created`, `response.in_progress`,
`response.output_item.added`, `response.image_generation_call.completed`,
`response.output_item.done`, `response.completed`. Для текстового результата
используются события `response.content_part.*` и `response.output_text.*`.
ID элемента стабилен между событиями и итоговым ответом, `sequence_number`
возрастает. Это выдача готового результата в формате SSE; живого прогресса
и частичных картинок нет. Ошибки до готовности возвращаются обычным JSON
с соответствующим HTTP-кодом. Расход неизвестен: `usage: null`,
`X-Rotator-Usage: unavailable`. Ответы не кэшируются (`no-store`).

В `POST /v1beta/models/<model>:generateContent` и `:streamGenerateContent`
картинки включаются через стандартные
[`generationConfig.responseModalities`](https://ai.google.dev/gemini-api/docs/generate-content/image-generation):

```json
{
  "contents": [{ "role": "user", "parts": [{ "text": "Нарисуй зелёного робота" }] }],
  "generationConfig": { "responseModalities": ["TEXT", "IMAGE"] }
}
```

`["TEXT", "IMAGE"]` допускает текст либо картинку; `["IMAGE"]` требует
картинку. Ответ содержит `candidates[0].content.parts[].inlineData`
с `mimeType` и base64 `data` либо обычный текст. Потоковый вариант выдаёт
готовый результат одним SSE-пакетом. `imageConfig` и сочетание с function
tools не поддерживаются; счётчики `usageMetadata` не выдумываются.

В стандартных схемах ответа
[Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)
и [Anthropic Messages](https://platform.claude.com/docs/en/api/messages/create)
нет аналогичного блока для созданного изображения. Эти маршруты продолжают
поддерживать входные картинки, текст и клиентские function tools.
Для получения созданной картинки оболочка должна вызывать Images API,
Responses с `image_generation` либо Gemini с IMAGE-модальностью.
Ротатор не добавляет нестандартные `message.images` и не подменяет картинку
ссылкой на приватный ресурс Google.

Реальная проверка Images API 16 октября 2026 года: в изолированном контейнере с копией
сессии запрос через HTTP на `gemini-4-argon-web-low` вернул 200 и JPEG
1376×768 (50 476 байт) за 23,68 секунды. Файл декодирован и просмотрен;
внутренних URL и cookies в ответе нет, аккаунт освобождён. Хеши проверенных
исходников совпали с локальными. Для Medium/High реальная генерация картинок

## Экспериментальные инструменты через совместимые API

Клиент передаёт OpenAI function-объявления с произвольными именами, описаниями
и JSON Schema аргументов. Привязки к названиям или формату инструментов OMP нет:
`read_file`, `execute_command`, MCP-функции и другие объявления проходят тот же
мост. Инструменты исполняет клиент; MCP-подключения на сервере не создаются.
Поддерживаются `tool_choice: auto`, `none`, `required` и выбор функции по имени.
Для Anthropic используются соответствующие `auto`, `none`, `any`, `tool`.
При обязательном вызове обычный текст и выбор другой функции не передаются
клиенту: допускается одна повторная генерация, затем возвращается 502.
Общий каталог по-прежнему
не обещает полноценный tool calling. Каждый ответ может запросить один инструмент;
следующие вызовы выполняются после получения результата предыдущего.

Локальными HTTP-тестами с имитацией worker проверены function tools через
`/v1/chat/completions`, `/v1/responses` и `/v1/messages`: обычные и SSE-ответы,
выбор функции, возврат результата с ID вызова и следующий текстовый ответ.
Responses поддерживает продолжение по `previous_response_id` через существующее
хранилище ротатора. Эти тесты подтверждают формат API; надёжность выполнения
инструкций настоящим Argon проверяется отдельно.
Нужна оболочка, позволяющая указать собственные endpoint и модель; встроенные
сервисы провайдеров (web search, computer use и другие) не эмулируются.

16 октября 2026 года в отдельной тестовой копии на сервере проверен настоящий
Argon: все три endpoint прошли цикл вызов функции → результат клиента → ответ
как с обычной выдачей, так и через SSE. Использовались `low` для Chat Completions
и Anthropic Messages, `medium` для Responses. Код проверки создавался случайно
после вызова функции, поэтому модель могла получить его только из результата.
Обычный OMP 18.4.5 с отключёнными расширениями также выполнил `read` и вернул
точный код из файла. Это проверка отдельных сценариев, а не всех оболочек.

При проверках также наблюдались тайм-аут продолжения на `high` (180 секунд
ожидания клиента) и 409 после 60 секунд ожидания занятой сессии. Последовательные
SSE-проверки на одном аккаунте прошли. Нативная надёжность tool calling
не заявляется.

Брокер ограничивает обработку запроса 450 секундами с учётом ожидания блокировки;
закрытие клиента при ошибке или отмене получает отдельный предел 5 секунд.
Ожидание занятой сессии ограничено 60 секундами и заканчивается 409. Отмена
ожидающего запроса не прерывает активную генерацию. После ошибки или отмены
активного запроса блокировка освобождается, а следующее обращение создаёт клиент
заново, используя сохранённую сессию.

Тестами с имитацией upstream проверены общий срок обработки, зависшее закрытие
клиента, восстановление после ошибки и отмена ожидающего запроса. HTTP-тесты
проверяют остановку worker и освобождение слота аккаунта при отключении клиента
во всех трёх API, с обычным ответом и SSE.

16 октября 2026 года на настоящем Argon в отдельном контейнере с копией сессии
прошли отмена ожидающего запроса без остановки активного ответа, отмена активного
ответа и новый запрос на том же аккаунте. Блокировка после отмены освободилась
за 0,02 секунды. Также проверены ответ 504 по общему таймауту и успешный запрос
после него; только в проверке таймаут был сокращён с 450 до 3 секунд.
Оба запроса после восстановления вернули точный случайный код.

Этот прогон выявил зависание при отмене: завершение HTTP-потока в `curl_cffi`
ждало закрытия транспорта, а брокер закрывал транспорт после завершения задачи.
Теперь брокер отменяет задачу, закрывает клиент и затем ждёт завершения задачи;
регрессионный тест воспроизводит эту зависимость при отмене и таймауте.
Полный интервал 450 секунд не выдерживался; скорость завершения обычного ответа
Google и надёжность других режимов этими проверками не гарантируются.

Поддерживаемая часть JSON Schema:

- `object`, `array`, `string`, `number`, `integer`, `boolean`, `null` и массивы типов;
- вложенные `properties`, `required`, `items`, `additionalProperties` (boolean
  или схема; при отсутствии дополнительные свойства разрешены);
- `enum`, `const`, `anyOf`, `oneOf`, `allOf`, а также совместимый `nullable`;
- `minimum`, `maximum`, числовые `exclusiveMinimum` / `exclusiveMaximum`,
  `minLength` / `maxLength`, `minItems` / `maxItems`, `minProperties` / `maxProperties`;
- аннотации `$schema`, `title`, `description`, `default`, `examples`, `deprecated`,
  `readOnly`, `writeOnly`. Значения по умолчанию не подставляются.

Схемы сохраняются без преобразования в ограниченный формат нативного Gemini API.
Имена свойств не интерпретируются как ключевые слова схемы. Неизвестные ключевые
слова, включая `$ref`, `$defs`, `pattern` и `format`, возвращают 400 с путём
проблемы до запуска worker. Поддержка всех конструкций JSON Schema не заявляется.
Глубина схем ограничена 32 уровнями, число узлов — 2048; проверка аргументов
также ограничена по глубине и числу операций. Неверные аргументы не передаются
клиенту. Отсутствие `parameters` означает объект без дополнительных ограничений.

Адаптер описывает инструменты веб-модели текстом и принимает вызов
только с уникальным маркером текущего запроса. Имя и аргументы проверяются,
ответ преобразуется в стандартный `tool_calls`. Инструменты выполняет клиент на
своей машине, затем отправляет сообщение `role: tool`. Результат включается
в следующий запрос целиком в пределах общего лимита 4 МиБ. Для этого
режима ответ буферизуется до завершения; обычный текстовый чат остаётся
потоковым. Это эмуляция инструментов через текст, а не нативный API Gemini.

Формат патча, пути, ограничения команд и допустимость фонового исполнения
задаются описаниями и схемами конкретного клиента. Адаптер не добавляет
собственные правила по названию `read`, `edit` или `bash`. Проверка snapshot-меток,
применение патчей и разрешения остаются на стороне клиента. Ошибки инструментов
передаются модели в истории как результаты неудачных операций.

История сохраняет имя инструмента и ID как в вызове, так и в результате.
Это позволяет сопоставить полученные данные с выполненной операцией;
регрессионный тест проверяет эту связь после преобразования запроса в веб-промпт.

## Диагностика

В обычную команду `doctor` добавлены проверки Gemini Web:

```sh
node --import tsx/esm src/cli.ts doctor
```

Она проверяет Python 3.11+, импорт worker/session и `gemini_webapi`, а также
доступность и формат файлов cookies у настроенных аккаунтов. Запросов к Google
нет: корректный JSON ещё не означает, что сессия действует или имеет доступ к Argon.
Интерпретатор берётся из `TUXEVIL_ROTATOR_GEMINI_WEB_PYTHON` либо `python3`.
Локальная проверка Python ограничена пятью секундами.

Для проверки авторизации и наличия Argon используйте явный флаг:

```sh
node --import tsx/esm src/cli.ts doctor --gemini-web-probe
```

Запускайте команду в том же окружении и с тем же config-dir, что и сервер:
в контейнере пути cookies и интерпретатор могут отличаться от хоста. Проверка
использует настроенный proxy каждого аккаунта, идёт последовательно и ограничена
90 секундами на аккаунт. Она обращается к Gemini App и может обновить сохранённую
сессию, но не генерирует ответ, не проверяет уровни размышления и инструменты и
не меняет переключатели провайдеров или моделей.

Отчёт `geminiWeb` содержит режим, число аккаунтов, код каждой проверки и действие
для восстановления. Различаются `auth-required`, `argon-unavailable`,
`session-busy`, `rate-limited`, `blocked`, `timeout`, `protocol-error` и прочие
сбои. Ошибки дают ненулевой код завершения. Cookies, содержимое ответов и тексты
исключений Python в отчёт не включаются. Если локальный runtime или файл cookies
не прошли проверку, сетевой запрос для такого аккаунта не выполняется.

В штатных записях `[gemini-web]` поле `timingsMs` также содержит
`googleHeaders`, `googleFirstChunk` и `googleStreamEnd`: время от начала POST
генерации до получения заголовков, первого непустого сетевого фрагмента и
полного чтения потока соответственно. При повторах значения суммируются по
HTTP-запросам; это пересекающиеся замеры, складывать их между собой нельзя.
Отсутствующее событие не записывается: например, при обрыве потока не будет
`googleStreamEnd`. Первый фрагмент может содержать служебные данные, а не текст
ответа. Содержимое заголовков и фрагментов не журналируется. Эти метрики
передаются только во внутреннюю диагностику, без изменения ответа API и
проверки идентификатора модели.

Для текстовых ответов дополнительно записываются отметки от начала обработки
запроса брокером (включая `sessionWait`):

- `firstText` — первый непустой текстовый фрагмент, разобранный библиотекой;
- `responseStreamEnd` — полное чтение последнего завершённого потока Google;
- `modelVerified` — успешная итоговая проверка модели перед завершением ответа;
- `firstOutput` — передача первого текстового фрагмента из воркера в ротатор.

`firstText` сохраняется и для впоследствии отклонённой попытки. При повторах
первая отметка не перезаписывается, а `responseStreamEnd` и `modelVerified`
относятся к последнему соответствующему событию. Разность `firstOutput` и
`firstText` показывает удержание текста внутри воркера, включая возможные
повторы. Это не время доставки до экрана Pi. `modelVerification` — отдельная
суммарная длительность разбора и проверки метаданных в конце потоков, а не
отметка времени. `firstOutput` может предшествовать `modelVerified`. На оборванном
потоке остаются `firstText` и `firstOutput`, если текст успел прийти и выйти;
отсутствующие завершение, проверка и выпуск текста не подставляются
нулями. Значения этих полей — только целые миллисекунды; текст не сохраняется.


Тесты не используют настоящие cookies и не обращаются к Gemini App. Они
проверяют выбор Argon без fallback, историю, Unicode, SSE, ошибки до и после
начала потока, блокировку сессии, ограничение вывода и отмену worker. Отдельные
проверки запускают настоящий постоянный процесс с имитацией Google-клиента:
повторное использование, фоновое обновление и восстановление cache после
перезапуска. Вход проверяется на тестовой SQLite-базе Firefox, перенос по SSH —
на имитации сервера, включая откат cookies при отказе авторизации.
